# Rencana: Admin Area SeoTool.im (User Management, Billing/PayPal, Pricing, API Keys, Blog CMS, Pages CMS)

Otoritas admin memakai mekanisme existing: `PLATFORM_ADMIN_USER_IDS` (env allowlist) + middleware `requirePlatformAdmin` + `checkIsPlatformAdmin`. Tidak ada sistem auth baru, murni tambahan fitur. Semua keputusan arsitektur sudah dikonfirmasi: CMS = DB + render aplikasi, API key = status + edit DB, user mgmt = Better Auth admin plugin, pricing = DB + sync PayPal.

## Struktur Route Baru (semua di bawah `src/routes/_app/admin/`)

- `route.tsx` (BARU): layout admin berisi `beforeLoad` cek admin (pindahkan dari `index.tsx`), non-admin tetap lihat 404 (pola existing), plus tab navigasi admin
- `index.tsx`: Overview = AdminDashboard existing + panel operasional baru (status provider, signup terbaru)
- `users/index.tsx` (list+search) dan `users/$userId.tsx` (detail + aksi)
- `billing/index.tsx` (subscriptions + log webhook + aksi kredit)
- `pricing/index.tsx` (editor harga per tier)
- `blog/index.tsx` (list) dan `blog/$postId.tsx` (editor, termasuk create baru)
- `pages/index.tsx` dan `pages/$postId.tsx`
- `api-keys/index.tsx` (status board + edit nilai)

Route publik baru untuk konten CMS: `blogs/index.tsx`, `blogs/$slug.tsx`, `pages/$slug.tsx`, plus 5 route legal fixed (`privacy.tsx`, `terms-and-conditions.tsx`, `cookie-policy.tsx`, `refund-policy.tsx`, `dpa.tsx`) yang membaca `cms_pages`. Render publik memakai **route loader** (bukan server function) yang memanggil repository langsung, sehingga bebas dari middleware ensureUser/paywall; meta SEO via `head()`.

## Server Functions Baru (`src/serverFunctions/`)

`admin-users.ts`, `admin-billing.ts`, `admin-pricing.ts`, `admin-content.ts`, `admin-settings.ts`. Pola: `.middleware([requireAuthenticatedContext, requirePlatformAdmin])` + `.validator(zodSchema)` (schema di `src/types/schemas/`) → service → repository (konvensi AGENTS.md). Semua file ini **ditambahkan ke `ALWAYS_ALLOWED_FILES`** di `src/middleware/paid-plan-gate.ts` agar admin dengan org free tidak terkena paywall, dan **`use-paid-plan-guard.ts`** di-exempt untuk path `/admin`.

## Tabel DB Baru (kedua dialek sqlite+pg, barrel export `src/db/schema.ts`, parity test)

1. `plan_config`: tier (PK), price_usd_cents, monthly_credits, paypal_plan_id, sync_status (synced/pending/failed), active, updated_at, updated_by_user_id
2. `cms_posts`: id, slug unique, title, description, content_md, status draft/published, published_at, created_at, updated_at, author_user_id
3. `cms_pages`: id, slug unique, title, content_md, status, updated_at, updated_by_user_id
4. `app_settings`: key (PK), value, is_secret, updated_at, updated_by_user_id
5. `paypal_webhook_events`: id, event_type, organization_id, payload, status, error, received_at (audit/debug)
6. Kolom Better Auth admin plugin di tabel user/session (banned, ban_reason, ban_expires, ban_count, role, impersonated_by) via `pnpm auth:generate:pg` + `auth:generate:d1`

## Fase Implementasi

**Fase 1 — Fondasi**: layout admin + nav link "Admin" di Sidebar (gated hasil `checkIsPlatformAdmin`, cache useQuery), exempt paywall client+server, tabel `app_settings` + layer override `runtime-env.ts` (DB dulu dengan cache in-memory 60s, fallback env; nilai `is_secret` tidak pernah dikirim ke browser), UI `/admin/api-keys` (status semua provider: DataForSEO, OpenRouter, PayPal, Loops, Google, Turnstile, PostHog, Reddit + edit masked).

**Fase 2 — User Management**: aktifkan plugin Better Auth `admin()` server + `adminClient()` client + migrasi. List/search user (AppDataTable), detail user (org, role, tier subscription, saldo kredit, sesi), aksi: ban/unban dengan alasan (enforcement otomatis di getSession oleh plugin), force logout (revoke sessions), ubah tier manual, adjust kredit. `PLATFORM_ADMIN_USER_IDS` tetap otoritas tunggal; role plugin tidak dipakai untuk gating. Impersonation sengaja tidak diekspos di UI v1.

**Fase 3 — Billing & PayPal Admin**: list subscription (join org + user), aksi per org: resync dari PayPal (reuse `syncPaypalCustomerStatus`), override tier manual (reuse logika upsert + re-grant kredit), adjust kredit dengan alasan. Tabel `paypal_webhook_events` + insert di handler webhook + viewer. **Termasuk bug fix penting**: top-up PayPal saat ini tidak pernah memberi kredit (`addTopupCredits` tidak punya caller sama sekali — user bayar tapi kredit tidak masuk). Fix: pada `PAYMENT.CAPTURE.COMPLETED` dengan reference_id `topup-{orgId}-{ts}`, konversi amount USD ke kredit (`CREDITS_PER_USD`) lalu panggil `addTopupCredits`.

**Fase 4 — Pricing Editor**: `PlanConfigService.getEffectivePlanConfig()` merge DB di atas konstanta `shared/plans.ts`. Refactor konsumen harga (PlanPickerGrid, /billing, MRR di AdminDashboard + AnalyticsRepository, PricingSection SaaS) ke effective config. UI `/admin/pricing` per tier (harga USD, monthly credits, active) + tombol save yang juga memanggil PayPal `PATCH /v1/billing/plans/{id}/update-pricing-scheme` (facade baru di `src/server/billing/paypal.ts`); gagal sync = status pending + banner peringatan. Catatan: halaman pricing marketing (`web/`) tetap statis sampai rebuild marketing berikutnya (didokumentasikan).

**Fase 5 — Blog CMS**: CmsService (slug validation kebabcase + unique, publish/unpublish, delete), UI admin list+editor (TanStack Form, preview via komponen `Markdown` existing), route publik `/blogs` + `/blogs/$slug` dengan meta SEO, seed 3 post markdown existing dari `web/content/blogs/` ke DB, update matcher Caddyfile (root, `gateway-caddy/Caddyfile`, `Caddyfile.seotool`): `/blogs*` dialihkan dari static marketing ke `open-sea:3001`, tambah prefix publik `/blogs` di `unauthenticated-redirect.ts`.

**Fase 6 — Pages CMS**: sama pola dengan blog untuk halaman. Route legal fixed membaca `cms_pages` (fallback konten statis jika row kosong, aman sebelum seed) + `/pages/$slug` untuk halaman custom. Seed isi `web/content/legal/*.md`. Alihkan path legal di Caddyfile ke aplikasi + tambah prefix publik.

**Fase 7 — Polish & Deploy**: unit tests (merge PlanConfig, slug CmsService, grant topup, guard admin; mock quota-gate/QuotaRepository sesuai pola test existing), update parity test schema, `npx @tanstack/router-cli generate`, oxlint/tsc/prettier clean, migrasi PG di VPS via docker, reload Caddy, tulis `docs/ADMIN.md`.

## Konvensi yang Dijaga

- oxlint max-lines 400 (pecah file bila perlu), AppError dari `error-codes.ts`, DaisyUI dua tema sinkron dengan token semantik per DESIGN.md, toolkit AppDataTable/Modal/SegmentedToggle, TanStack Form + toast sonner, tanpa em-dash di copy Inggris, tabel baru dua dialek + barrel export (gotcha existing).

## Risiko yang Sudah Dipetakan

- PayPal update-pricing-scheme punya batasan; fallback status pending-sync dengan instruksi manual.
- Secrets di DB tidak pernah dibaca balik ke client (write-only + flag configured).
- Marketing site (web/) tidak realtime untuk pricing/blog lama; hanya path yang dialihkan Caddy yang melayani DB.
- E2E admin route: non-admin mendapat 404 (pola existing dipertahankan).
