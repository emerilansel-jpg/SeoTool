## Phase 3 (Content Intelligence) — Slice A: Deterministic Content-Quality Scoring

### Goal

Per-page content-quality score (0–100) with explainable sub-scores, computed from **already-crawled** `audit_pages` signals (no new external API, no cost, no deps). Persisted per audit page. Surfaced as a new **"Content" tab** in the audit results UI. Foundation that later entity-gap (DataForSEO) topical/LLM (OpenRouter) slices build on.

### Architecture seam (clean separation)

- **Content-intelligence feature** owns: schema, pure scoring engine, repository, service, server fns, client view, MCP tool.
- **Audit workflow** owns: one new phase that reads `audit_pages` calls `ContentIntelligenceService.computeScoresForAudit(auditId)`.
- Client surfaces via lazy `useQuery` on the Content tab only (no bloating `AuditResultsData`).

### File-by-file

**Schema (dual-dialect, mirror ga4/reports pattern)**

1. `src/db/content-intelligence.schema.ts` (SQLite, NEW) — table `content_scores`:
   - `id text PK`, `auditId text FK→audits cascade`, `pageId text FK→audit_pages cascade`, `url text`, `score real 0-100` (overall)
   - sub-scores `real 0-100`: `depthScore`, `headingsScore`, `metadataScore`, `mediaScore`, `linkingScore`, `technicalScore`
   - `flagsJson text` (array of `{severity:"critical"|"warning"|"info", code, message}`)
   - `wordCount integer`, `computedAt text default (current_timestamp)`
   - indexes: `(auditId)`, `(pageId)`, `unique(pageId)`
2. `src/db/pg/content-intelligence.schema.ts` (Postgres, NEW) — identical columns (boolean→`boolean`, real→`real`, text→`text`, timestamp default→`isoNow` pattern per reports schema)
3. `src/db/d1/schema.ts` EDIT — `export "../content-intelligence.schema";`
4. `src/db/pg/schema.ts` EDIT — `export "./content-intelligence.schema";`
5. Run `pnpm db:generate:d1` `pnpm db:generate:pg` → generates `drizzle/0039_*` + `drizzle-pg/0016_*` (auto)

**Scoring engine (pure, heavily unit-tested — the heart)** 6. `src/server/features/content-intelligence/contentScore.ts` (NEW) — pure `scoreContent(input: ContentScoreInput): ContentScoreResult`. Input derived from audit_pages row (wordCount, h1–h6, title/meta/og lengths, imagesTotal/imagesMissingAlt, internal/external link counts, hasStructuredData, isIndexable, canonical, robotsMeta). Weighted sub-scores → overall; returns sub-scores + flags array. Transparent SEO best-practice thresholds (documented in comments).

- Weights: depth 25, headings 20, metadata 20, technical 15, media 10, linking 10.

7. `src/server/features/content-intelligence/contentScore.test.ts` (NEW) — ~14 cases: thin content, ideal length, missing h1, multiple h1, skipped heading levels, missing/overlong title meta, missing alt, noindex tanks technical, no structured data, canonical missing, perfect page = high score, etc.

**Repository / Service** 8. `src/server/features/content-intelligence/repositories/ContentScoreRepository.ts` (NEW) — `bulkUpsertForAudit(auditId, rows)`, `listForAudit(auditId)`, `getForPage(pageId)`, `clearForAudit(auditId)`. 9. `src/server/features/content-intelligence/services/ContentIntelligenceService.ts` (NEW) — `computeScoresForAudit(auditId)` (read pages, score each, bulkUpsert; tolerant: skips non-ok/blocked pages), `getScoresForAudit(auditId, projectId)`, `getSummary(auditId, projectId)` (avg + distribution buckets poor<40/fair<70/good<90/excellent≥90).

**Workflow integration** 10. `src/server/workflows/siteAuditWorkflowPhases.ts` EDIT — add `runContentScoringPhase` (pgStep batch), invoked after `runCrawlPhase`. Cheap compute + DB writes only.

**Server functions (array-form middleware)** 11. `src/serverFunctions/content-intelligence.ts` (NEW) — `getContentScores` (GET, `[requireProjectContext]`, viewer+), `getContentScoreSummary` (GET, `[requireProjectContext]`). 12. `src/types/schemas/content-intelligence.ts` (NEW) — zod `auditIdInputSchema`, project-scoped.

**Client UI** 13. `src/client/features/content-intelligence/ContentScoresView.tsx` (NEW) — summary cards (avg score, distribution), sortable table (page, score badge, sub-score mini-bars), drill-down flags panel. 14. `src/client/features/content-intelligence/ContentScoresParts.tsx` (NEW) — `ScoreBadge`, `SubScoreBar`, `SummaryCards`, reuse `scoreClass` colors from existing audit shared styling. 15. `src/client/features/audit/results/ResultsView.tsx` EDIT — add `"content"` to the `ResultsTab` union + tab button (lazy `useQuery(getContentScores)` only when active).

### Risks / mitigations

- **Brace-stripping hazard** (coldstart §Bug lingkungan): every new TS file verified brace-balance via `node -e` after write. Prefer fewer-larger writes; fall back to line/regex patch if `Write` corrupts.
- **Scoring thresholds** are opinionated — documented + unit-tested so they're tunable later.
- Workflow phase must be tolerant (blocked/errored pages skipped, not fatal) — mirrors existing multipage-checks error handling.
