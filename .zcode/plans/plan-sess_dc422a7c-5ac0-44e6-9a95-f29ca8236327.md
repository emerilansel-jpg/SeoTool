# Fase 2 — Custom Reports (Hybrid PDF + Full RBAC foundation)

## Keputusan desain (dari jawaban Anda)

- **Hybrid PDF**: snapshot data JSON di server sesuai jadwal → email berisi LINK ke report in-app (recharts penuh) → tombol "Download PDF" render client-side (jsPDF + jspdf-autotable) → "Export CSV" reuse `csv.ts`. Nol server-side PDF rendering, nol binding baru.
- **Full RBAC**: surface `member.role` ke context + role-checking middleware. Roles: `owner > admin > manager > viewer`. viewer = client-viewer (read-only). Scope = role resolution + gating; rebuild penuh Better-Auth org/invitation management UI = fase terpisah (di luar lingkup).
- **Snapshot = JSON text** di `report_snapshots.data`. Justified: payload heterogen immutable (rank rows + audit counts + gsc/ga4 totals + backlinks), bukan data relasional. Precedent: backlinkSnapshots (flat), namun report snapshot heterogen → JSON. Repo rule "no relational data in JSON" tidak dilanggar (ini payload, bukan relasi).
- **Branding per-report** (bukan per-org): agency buat report per-klien → branding (clientName, logoUrl, brandColor, accentColor) kolom di tabel `reports`. Bersih & typed, tidak sentuh better-auth schema (yang ter-regenerate `auth:generate`).
- **Reuse**: DashboardService (rank/audit/backlinks), GA4 `analyticsReport.ts` + GSC `searchPerformanceReport.ts` pure shapers, `Ga4Service`/`GscService`, Loops `sendLoopsTransactionalEmail` pattern, `csv.ts`, Workflow pattern (`WorkflowEntrypoint` + `pgStep`).

## Sub-fase 2B — Data model + CRUD

- **New** `src/db/reports.schema.ts` (D1) + `src/db/pg/reports.schema.ts`:
  - `reports`: id, organizationId (FK org), projectId (FK projects CASCADE), name, schedule (`none|weekly|monthly`), dayOfWeek (int nullable), dayOfMonth (int nullable), nextRunAt (text nullable ISO), clientName, logoUrl, brandColor, accentColor, createdByUserId, createdAt, updatedAt. Index (organizationId), index (projectId), index (nextRunAt) untuk cron query.
  - `report_sections`: id, reportId (FK reports CASCADE), type (`rank|audit|gsc|ga4|backlinks`), config (text JSON — section params: dateRange dll; config bukan relasi), sortOrder (int).

  - `report_deliveries`: id, snapshotId (FK snapshots CASCADE), channel (`email`), recipients (text JSON array), status (`pending|sent|failed`), sentAt, error.
- **Modify** barrels (`d1/schema.ts`, `pg/schema.ts`, `schema.ts` AppSchema + runtime + destructure), `schema-parity.test.ts` (kedua `tablesFrom`).

## Sub-fase 2C — Snapshot generation (data aggregation)

- **New** `src/server/features/reports/services/ReportSnapshotBuilder.ts`: pure-ish aggregator. Input report config + sections → panggil `DashboardService.getOverview` (rank/audit/backlinks), `GscService.getPerformance`, `Ga4Service.getReport` per section → shape ke payload `{ generatedAt, range, sections: { rank:{...}, audit:{...}, gsc:{...}, ga4:{...}, backlinks:{...} } }`. ## Definition of Done Fase 2

- Admin/manager create report config (sections + schedule + branding) → generate snapshot (on-demand) → view in-app dengan branding + charts + tables → download PDF (client jsPDF) + CSV.
- Scheduled report (weekly/monthly): cron dispatch Workflow → snapshot dibuat → email link ke recipient.
- RBAC: viewer hanya view (CRUD di-block), manager+ admin CRUD.
- Dual-dialect migrate jalan; ci:check + test:ci lulus.

## Catatan & risiko

- **better-auth custom roles**: perlu verifikasi API org plugin (`customRoles` option) versi terinstal saat impl. Bila API beda, fallback: simpan role text tanpa validasi plugin (DB column text tetap terima).
- **jsPDF bundle size**: client-only dep, tidak membebani Worker bundle.
- **Snapshot JSON size**: cap section rows (spt export limits) supaya tidak bengkak. Omit raw row arrays, simpan top-N + totals.
- **Email delivery soft-fail**: bila `LOOPS_TRANSACTIONAL_REPORT_ID` unset → log + skip, snapshot tetap dibuat (delivery non-blocking).
- **RBAC rebuild org UI out of scope**: role bisa di-set via invitation/member API Better-Auth; UI manajemen member penuh = fase terpisah.
