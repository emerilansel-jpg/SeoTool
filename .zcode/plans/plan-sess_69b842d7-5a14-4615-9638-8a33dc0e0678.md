# Implementation Plan: Homepage Fix + SaaS Billing System

## Problem 1: Homepage redirects to dashboard

### Root Cause
VPS hanya menjalankan SaaS app (`src/`). Marketing site (`web/`) tidak pernah di-build atau di-deploy. DNS `seotool.im` menunjuk ke VPS → Caddy → SaaS app, yang route `/` nya adalah redirect ke dashboard/sign-in.

### Solution: Serve marketing static files via Caddy + proxy fallback

Semua di satu domain `seotool.im`, tanpa subdomain, tanpa DNS changes.

#### Step 1: Update `docker-compose.hosted.yaml`
Add marketing build as a separate service, mount output to Caddy:

```yaml
services:
  marketing-build:
    build:
      context: ./web
      dockerfile: Dockerfile.marketing  # baru: build web/ → /srv/marketing
    # Atau lebih simple: pre-build step di deploy script

  caddy:
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
      - ./web/dist/client:/srv/marketing:ro  # TAMBAHAN: mount marketing static
```

#### Step 2: Update `scripts/deploy-vps.sh`
Add marketing build before docker compose up:

```bash
# Build marketing site
echo "Building marketing site..."
cd web && pnpm install --frozen-lockfile && pnpm run build && cd ..

# Build & start SaaS app + Caddy
docker compose -f docker-compose.hosted.yaml --env-file .env.hosted up -d --build
```

#### Step 3: Update `Caddyfile` 
Route static marketing files first, proxy everything else to SaaS:

```caddyfile
seotool.im {
    # Marketing static files (prerendered HTML)
    @staticFiles {
        file {
            root /srv/marketing
            try_files {path} {path}/index.html
        }
    }
    handle @staticFiles {
        root * /srv/marketing
        file_server
    }

    # Everything else → SaaS app
    handle {
        reverse_proxy open-seo:3001
    }

    encode gzip zstd
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options "nosniff"
    }

    @websockets {
        header Connection *Upgrade*
        header Upgrade websocket
    }
    reverse_proxy @websockets open-seo:3001
}
```

**How it works:**
- User visits `seotool.im/` → Caddy finds `/srv/marketing/index.html` → serves marketing homepage
- User visits `seotool.im/pricing` → Caddy finds `/srv/marketing/pricing/index.html` → serves pricing page
- User visits `seotool.im/sign-in` → No static file → falls through to SaaS proxy → sign-in page
- User visits `seotool.im/api/health` → No static file → falls through to SaaS proxy

#### Step 4: Update cross-app links
Change all `https://seotool.im/sign-in` in marketing to `/sign-in` (relative, since same domain now). Already done during rebrand - verify no broken absolute links remain.

## Problem 2: SaaS Pricing/Billing (Sell quotas like Semrush)

### Current State: ALREADY BUILT

The billing system **already supports** the exact model you want:
- **Owner provides API keys**: `DATAFORSEO_API_KEY` and `OPENROUTER_API_KEY` are global env vars, shared across all users
- **Users buy quotas**: 4 tiers (Free $0 / Lite $49 / Pro $149 / Agency $499) with per-feature limits
- **Markup baked in**: 1.28x markup on DataForSEO costs, tracked via Autumn credits
- **Stripe checkout**: Via Autumn (sits on top of Stripe)
- **Quota enforcement**: Every API call checks quota before executing

### What needs to be CONFIGURED (not coded):

#### Step 1: Set up Autumn account
1. Create account at https://useautumn.com
2. Connect your Stripe account to Autumn
3. Create 4 products in Autumn dashboard:
   - `lite-plan` ($49/month)
   - `pro-plan` ($149/month)
   - `agency-plan` ($499/month)
   - Free tier = Autumn Default (auto-assigned at signup)
4. Set up credit features in Autumn:
   - `usage_credits` (monthly, included with paid plans)
   - `topup_credits` (one-time purchases)
5. Copy `AUTUMN_SECRET_KEY`

#### Step 2: Set environment variables in `.env.hosted`
```env
# API Keys (OWNER provides these - users never see them)
DATAFORSEO_API_KEY=your_base64_encoded_dfs_key
OPENROUTER_API_KEY=sk-or-...

# Billing
AUTUMN_SECRET_KEY=autumn_sk_...

# Auth
BETTER_AUTH_URL=https://seotool.im
BETTER_AUTH_SECRET=your_32_char_secret
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...

# Email (Loops or set BYPASS_EMAIL_VERIFICATION=true)
BYPASS_EMAIL_VERIFICATION=true  # for testing
```

#### Step 3: Verify quota enforcement works
The system already gates every API call:
```
User does keyword search
  → QuotaService.assertQuotaAvailable("keyword_search")
  → If quota exceeded → PLAN_LIMIT_REACHED error
  → If credits exhausted → INSUFFICIENT_CREDITS error
  → If OK → DataForSEO API called with OWNER's key
  → Usage tracked, credits deducted (cost × 1.28 markup)
```

#### Step 4: Test checkout flow
1. Sign up as a new user (Free tier)
2. Go to `/subscribe` or click "Upgrade"
3. Select a plan → Autumn checkout → Stripe payment
4. Verify quota upgrades take effect
5. Verify `/billing` page shows plan, usage bars, manage button

#### Step 5: (Optional) Configure Stripe Customer Portal
Already wired via `getCustomerPortalUrl()` in `serverFunctions/billing.ts`. Users can cancel/change payment methods from the portal.
